Design reference · for the coding agent

ColdSend should look like a tool, not a landing page.

Quiet neutral surfaces, one accent colour, hairline borders, real app density. Reference products: Linear, Superhuman, Claude, Attio, Notion Mail. Everything on this page is built from the tokens in section 4. Use the toggle (top right) to preview dark mode.

04 · Foundations

Design tokens

Light is the primary theme. Neutrals are warm stone-gray, not blue-gray. The accent appears only on primary buttons, focus rings, active progress and “needs attention” counts.

Shape, spacing, motion

  • Radius: 6 (small controls) · 8 (buttons, rows) · 12 (cards) · 14 (prompt box) · 999 (chips, badges)
  • Spacing on a 4px grid. Row heights: nav 30, list row 40–46, button 32 (28 small)
  • Borders are always 1px. Shadows only on popovers/menus and the prompt box (very faint)
  • Transitions 120ms, ease-out, colour and border only
  • No entrance animations on the home screen. Progress bars and the side panel may animate
  • Focus ring: 2px accent outline, plus a 3px 16% accent glow on the prompt box

Other screens to build with the same kit

  • Contacts / Database: dense table (row 40px), filter chips on top, row checkbox, slim detail drawer on the right (420px).

  • Settings / Context & files: two-column form, label left, input right, 1px dividers between groups.

Review-flow keyboard handler

useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    if (editing) { if (e.key === "Escape") saveAndExit(); return; }
    if ((e.target as HTMLElement).closest("input,textarea,[contenteditable]")) return;
    const k = e.key.toLowerCase();
    if (k === "y") approve(); else if (k === "n") skip(); else if (k === "e") setEditing(true);
    else if (e.key === "ArrowRight") next(); else if (e.key === "ArrowLeft") prev();
  };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, [editing, approve, skip, next, prev]);
07 · Guardrails

Rules for the agent building this

Do
  • Use only the CSS variables above. If a colour is not a token, don’t use it.
  • Keep one accent colour. Status colours (green/amber/red) appear only inside badges and dots.
  • Use 1px borders to separate things; let whitespace do the rest.
  • Keep rows compact: 30px nav, 40–46px list rows.
  • Make Y / N / E work from the keyboard everywhere in the review flow.
  • Write real placeholder data (names, companies, counts), never “Lorem ipsum” or “John Doe”.
  • Design light first, then verify dark.
Don’t
  • Gradients, gradient text, glows, glassmorphism, animated blobs or neon.
  • Feature grids of icon cards, or “trusted by” logo rows, inside the app.
  • Large stat cards as the focus of the home screen.
  • Heavy shadows or radius above 14px (except pills and avatars).
  • Emojis as icons. Use one thin-line icon set only.
  • Bold everywhere. Use 500 for emphasis, 600 only for titles.
  • Bootstrap-looking defaults: pure #fff on #f8f9fa, blue-600 buttons, default form controls.
